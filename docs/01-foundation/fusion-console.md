# Fusion console

## Objective

Demonstrate that the Fusion management experience is available and integrated with OpenShift.

## Procedure

Use the IBM Fusion release-specific console access procedure. Do not hard-code a route hostname because it is generated by the deployed environment.

Validate:

```bash
oc get routes -A
oc get pods -A
```

Then authenticate using the organization's approved OpenShift identity provider.

## Permissions

Use least privilege for operators. Installation privileges should not become permanent day-to-day permissions.

## Validation

- Fusion console loads.
- OpenShift user is authenticated.
- User can see only authorized services/resources.
- Service health is visible.
- No administrative secrets are displayed in screenshots.

## Evidence

Capture:

- console landing page;
- user/role context;
- service health;
- OpenShift route/resource evidence.
